# Visual Learning Docs

创建帮助读者快速建立心智模型的 Markdown 学习文档。图是主要的解释载体，文字负责补充图中不便表达的细节。

## 适用范围

当用户要编写以下内容时使用本 skill：

- 技术主题入门或快速学习文档
- “一图看懂”、概念图解、流程说明和简明教程
- 将零散知识整理成结构化 Markdown

不用于创建 Word、PDF、演示文稿或独立图片文件；所有结构化视觉解释默认使用 Mermaid。

## 核心原则

- 先明确读者、学习目标和范围，再决定文档结构。
- 优先帮助读者回答：这是什么、为什么需要、由什么组成、如何工作、何时使用。
- 图必须承载信息，不把 Mermaid 当装饰；一张图尽量只回答一个问题。
- 复杂主题拆成多张小图，默认将单张图控制在约 7～10 个节点以内。
- Mermaid 节点 ID 使用简单英文标识，显示文本可以使用中文。
- 图后只解释关键观察点，不重复抄写图中已经表达的内容。
- 不凭空补充项目事实；不确定或版本敏感的内容应标明假设，必要时查证可靠来源。

## 工作流

1. 判断主题、目标读者、学习目标和期望输出位置。信息不完整时，采用合理的入门级假设并在文档中说明。
2. 如果是修改已有 Markdown，先读取相关文档和同目录内容，识别术语、标题层级和写作风格。
3. 设计由浅入深的学习路径：问题/动机 → 总览 → 核心组成 → 工作过程 → 最小示例 → 常见误区 → 总结与自测。
4. 为每个需要视觉化的内容选择合适的 Mermaid 图：
   - 概念和层级：`mindmap` 或 `flowchart`
   - 流程和决策：`flowchart`
   - 调用顺序和交互：`sequenceDiagram`
   - 生命周期和状态变化：`stateDiagram`
   - 模块或对象关系：`classDiagram` 或 `flowchart`
5. 使用 fenced code block 编写 Mermaid 图。必要时重画、拆分、合并或替换已有图，不要求保留原有 Mermaid 图的结构。
6. 用短段落、列表和最小可运行示例补充图表；避免把快速学习文档写成完整参考手册。
7. 完成后检查图文一致性、Mermaid 围栏闭合、节点关系、标题层级、链接、代码块和术语使用。

## 默认输出结构

除非用户指定其他结构，优先使用：

````markdown
# 主题

> 一句话说明主题和学习收益。

## 先建立整体认识

```mermaid
flowchart LR
    input[输入] --> process[核心过程]
    process --> output[输出]
```

## 核心概念

## 它是怎么工作的

## 最小示例

## 常见误区

## 记忆要点

## 自测问题
````

根据主题删减不必要的章节；不要为了套模板强行添加图或内容。

## 验证

- 每篇文档至少有一张能表达主题整体结构的 Mermaid 图；纯文字定义不必强行绘图。
- 每张图都应与正文、示例和结论一致，不能出现图中不存在或正文未解释的关键关系。
- Mermaid 代码块应完整、可读，并尽量在目标 Markdown 渲染器中实际预览；若没有渲染工具，至少进行结构和语法级检查。
- 修改已有文档时，以准确性、学习路径和可读性为优先，不受原有 Mermaid 布局限制。
